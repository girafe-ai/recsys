# Поиск рекомендаций в Qdrant

Индексируем эмбеддинги объектов Last.fm, запросы — эмбеддинги пользователей.
Ищем по cosine similarity. Объекты и запросы явно L2-нормализуются для обоих методов.
Это нужно и для Qdrant: в Last.fm есть векторы с очень малой нормой,
которые его встроенная нормализация оставляет без изменений.
Эталон — `FAISS IndexFlatIP`.
`Qdrant exact` проверяет совпадение точного поиска и показывает время запроса через HTTP.
`Qdrant HNSW` измеряет приближённый поиск на тех же запросах.

Из этой директории:

```bash
python -m pip install -r requirements.txt
docker compose up -d
python operation.py
```

Данные автоматически скачиваются в `../data/lastfm_factors.h5`, если файла ещё нет.
Каждая строка `items` получает одинаковый ID в FAISS и Qdrant.
Перед замерами скрипт проверяет число загруженных точек и ждёт построения HNSW.
Ошибка загрузки прерывает запуск.

По умолчанию используются весь каталог, 256 случайных пользователей, прогрев
и три прохода по запросам в случайном порядке. Recall@k — доля соседей из точного
top-k, найденных методом, в среднем по пользователям. p50 и p95 — перцентили
времени одиночного запроса. Для Qdrant сюда входит HTTP, для FAISS — локальный вызов.
Это последовательные запросы без конкурентной нагрузки; по ним нельзя судить
о максимальном QPS сервиса. Результаты и параметры сохраняются в `results/benchmark.json`.

Параметры в `conf.yaml`:

- `hnsw_m`: число связей узла HNSW. Больше связей — выше связность графа,
  но больше памяти и работы при построении.
- `ef_construct`: размер множества кандидатов при построении графа.
  Увеличение обычно улучшает качество поиска, но замедляет построение.
- `hnsw_ef`: размер множества кандидатов при поиске. Увеличение повышает Recall
  ценой времени запроса. Должен быть не меньше `num_neighbours`.
- `num_neighbours`: размер выдачи и k в Recall@k.
- `num_embeddings`: ограничение каталога; `null` означает все объекты.
- `faiss_threads`: число потоков FAISS. Qdrant работает в отдельном контейнере
  и использует собственные потоки.

Во время загрузки построение индекса отключено (`indexing_threshold=0`).
После загрузки порог устанавливается в 1 КБ, чтобы небольшие сегменты тоже
индексировались. Замеры начинаются после перехода коллекции в `green`
и появления проиндексированных векторов.
`full_scan_threshold=10` КБ снижает порог, ниже которого Qdrant выбирает полный
перебор вместо HNSW: на этом каталоге сравниваем именно поиск по графу.

Существующая коллекция сохраняется. Для повторного запуска с её удалением:

```bash
python operation.py recreate=true
```

Другой размер выдачи или глубина поиска:

```bash
python operation.py recreate=true num_neighbours=100 hnsw_ef=1600
```

## Квантизация

По умолчанию `quantization.type=none`. Включить SQ8:

```bash
python operation.py recreate=true quantization.type=scalar
```

Настройки в блоке `quantization` файла `conf.yaml`:

| Параметр | Значения и смысл |
|---|---|
| `type` | `none`, `scalar`, `product`, `binary` |
| `quantile` | Для scalar: границы диапазона квантизации; `0.5–1.0`, `1.0` — весь диапазон. Более узкий диапазон уменьшает шаг, но сильнее обрезает хвосты |
| `compression` | Для product: `x4`, `x8`, `x16`, `x32`, `x64` — степень сжатия векторных кодов относительно float32. Codebook-и добавляют отдельные расходы |
| `always_ram` | Держать квантованные векторы в RAM, даже когда исходные векторы хранятся на диске |
| `rescore` | Пересчитывать оценки кандидатов по исходным float32-векторам |
| `oversampling` | Множитель числа кандидатов перед пересчётом: при `k=100` и значении `4` берём 400 кандидатов. Имеет смысл при `rescore=true` |

Product quantization:

```bash
python operation.py recreate=true quantization.type=product quantization.compression=x8
```

Binary quantization:

```bash
python operation.py recreate=true quantization.type=binary quantization.oversampling=4
```

Scalar, другой диапазон и поиск без пересчёта:

```bash
python operation.py recreate=true quantization.type=scalar quantization.quantile=0.95 quantization.rescore=false
```

При включённой квантизации в таблице появляется четвёртая строка с её типом.
Строка `Qdrant HNSW` использует исходные векторы (`ignore=true`), а новая строка —
квантованные, с выбранными `rescore` и `oversampling`. Оба поиска идут по одной коллекции.
`Qdrant exact` всегда выполняется по исходным векторам, независимо от настроек квантизации.

Scalar заменяет координаты на int8, product — части вектора на индексы центроидов,
binary — координаты на биты. Чем сильнее сжатие, тем важнее проверять Recall:
в частности, binary на 128-мерных эмбеддингах Last.fm может заметно терять качество.
Пересчёт улучшает порядок кандидатов, но не возвращает соседей, которых среди кандидатов нет.

Проверки без Docker:

```bash
python -m unittest -v test_operation.py
```

Проверка нормализации на настоящем сервере:

```bash
QDRANT_TEST_URL=http://127.0.0.1:6333 python -m unittest -v test_operation.py
```

Остановить контейнер, сохранив данные:

```bash
docker compose down
```

Qdrant хранит базу в Docker volume `qdrant_storage`. Он сохраняется после
`docker compose down` и не зависит от прав доступа к папкам проекта.

Если контейнер был запущен со старым `./storage:/qdrant/storage` и выдаёт
`Operation not permitted` при создании `storage/.deleted`, обновите ветку и выполните:

```bash
docker compose down
docker compose up -d
python operation.py recreate=true
```

Это создаст базу в новом volume и заново загрузит в неё эмбеддинги из HDF5.
Старая папка `storage`, если она есть, останется на месте.
